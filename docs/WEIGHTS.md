# Weight provenance and hosting

- Upstream: `princeton-vl/RAFT-Stereo/raftstereo-middlebury` — the checkpoint `raftstereo-middlebury.pth` of the RAFT-Stereo project (Lipson, Teed and Deng, 3DV 2021). This identifier names the upstream repository and the checkpoint file; it is not a Hugging Face Hub repository.
- Revision: `unpinned`. The checkpoint is **not yet pinned**. A file served from a URL has no commit, so its pinned revision will be the SHA-256 of the checkpoint's own bytes (the `.pth` member, not the archive, which the host may re-pack). `python tools/pin_snapshot.py` records it: it downloads the archive (or takes `--archive models.zip`), extracts the single member, hashes it, strict-loads it into the carried architecture and checks the parameter count, then writes the digest and byte size into the manifest and `src/raft_stereo_pipeline/pipeline.py`. It could not be run where this repository was built, because that environment cannot reach Dropbox; no digest has been invented in its place.
- Source URL: `https://www.dropbox.com/scl/fi/5khx1bhz84dapi8vtwapg/models.zip?rlkey=ggddrn1du1iiq6mgc2dsdpmwi&dl=1`, the link in upstream `download_models.sh` at commit `6e93ed2169bd858dbb43033988563f3b0bb49506` ("Fix Dropbox links", 2026-08-03). It needs no account or token. Upstream also lists a Google Drive folder; it is not used, so there is exactly one acquisition path and no fallback.
- Archive contents, per upstream's README and demo commands: `raftstereo-middlebury.pth`, `raftstereo-eth3d.pth`, `raftstereo-sceneflow.pth`, `raftstereo-realtime.pth` and `iraftstereo_rvc.pth`. Only `raftstereo-middlebury.pth` is extracted; the archive is deleted after extraction. The archive's own size and SHA-256 at pin time are recorded in the manifest for the record, not verified.
- Why this checkpoint: upstream recommends it for in-the-wild images, and its architecture is upstream's default (no architecture flag in the Middlebury demo command), so `MODEL_ARGS` are the demo defaults.
- Training, per the upstream paper and README: trained on SceneFlow (FlyingThings3D, Driving and Monkaa, rendered), then fine-tuned on the Middlebury 2014 training scenes (photographs). Those datasets are distributed under their own terms, which this repository did not review.
- Size: not yet measured. The carried architecture has 11,116,176 parameters in 337 state tensors; saving its DataParallel `state_dict` with the pinned `torch==2.14.0` gives 44,605,701 bytes, so the checkpoint is expected near 44.6 MB (an estimate, recorded so that a very different size is noticed). The planning record lists "~50.6 MB"; none of the upstream configurations serialises to that size (the real-time and instance-norm variants are smaller), so that figure is treated as unverified until the pin records the actual byte count.
- Weight format: a PyTorch `state_dict` saved with `torch.save` (`.pth`, pickle-based, keys prefixed `module.` by `torch.nn.DataParallel`). Upstream publishes no safe-tensor format.
- Manifest: `weights/raftstereo-middlebury/dimer-base-manifest.json`, format `dimer_url_snapshot`, one entry with `path`, `url` (the archive), `archiveMember`, `bytes` and `sha256`. While unpinned, `revision` is `"unpinned"`, and `bytes`, `sha256` and `totalBytes` are `null`.
- Upstream licence: MIT (Copyright (c) 2021 Princeton Vision & Learning Lab), covering the code and the released checkpoints.
- Hosting: the Git repository does not vendor the checkpoint (`weights/**/*.pth` is git-ignored). A fresh clone or a fresh notebook runtime stages it from the URL above.
- Fresh clone: `stage_missing_files(allow_download=True)` fetches only if the checkpoint is absent, only from the manifest URL, and only if that URL and file name equal the package's `WEIGHTS_ARCHIVE_URL` and `WEIGHTS_FILE`; `extract_member` takes exactly one member named `raftstereo-middlebury.pth` and refuses absolute paths, `..`, symbolic links and members over 512 MiB; `verify_snapshot()` then checks the byte size and SHA-256 before any load. A mismatch is never loaded and never replaced from another source.
- Loader trust boundary: `build_model()` constructs the carried upstream architecture with random weights and downloads nothing; `torch.load(<verified file>, map_location="cpu", weights_only=True)` restricts unpickling to tensors and plain containers, the `module.` prefix is stripped, and `load_state_dict(strict=True)` refuses a missing, unexpected or mis-shaped tensor.
- Model code trust boundary: the upstream `core/` files are carried at commit `6e93ed2169bd858dbb43033988563f3b0bb49506` and verified against `UPSTREAM_SHA256` before import; nothing is fetched or executed from the network as code. Upstream imports itself as the top-level package `core`; `load_upstream()` refuses to run if a different module named `core` is already imported.
