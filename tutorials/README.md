## Conformance notes

- **Standalone carrier (§4):** the default path performs no clone, repository install or repository import in the kernel. Section 2 writes the carried files into a fresh run directory and verifies each against `CARRIED_HASHES`; the package checks the upstream files again against `UPSTREAM_SHA256` before importing them.
- **Isolated environment (§5, §25.13):** a pinned `uv` wheel (size and SHA-256 checked) builds a managed CPython 3.12.12 environment and installs `requirements-colab.lock.txt` with `--require-hashes --only-binary :all:`; every stage runs there as a subprocess with `MPLBACKEND=Agg` and no Hugging Face token. Linux x86_64 only, refused clearly elsewhere.
- **Model acquisition (MOD1–MOD9):** the checkpoint is identified by the SHA-256 of its bytes once pinned; until then every loader refuses. The archive is fetched from upstream's Dropbox link without a credential, only the checkpoint member is extracted, its size and SHA-256 are verified, and it is read with `torch.load(..., weights_only=True)` and `load_state_dict(strict=True)`. No remote code is fetched.
- **Stages:** `validate_inputs` writes the input manifest with a rejection probe; `evaluation_report` scores the demonstration pair against SGBM (`sample-sanity`); two probes check sign and scale; `validate_dataset` validates the records and shows three refusals; the split is seeded and group-preserving; the baselines are configured on the training split; `finetune` runs the bounded adaptation from the verified checkpoint; the exported adapter is evaluated in a fresh process; unseen-pair disparity maps are exported; a second fresh process reloads the adapter and checks it against the trained in-memory model within a stated tolerance.
- **Uncertainty (UNC1–UNC6):** RAFT-Stereo outputs no confidence; every figure is a point estimate from one pass, printed next to its baselines, with no dispersion estimate.
- **Non-interactive execution (EXE1–EXE4):** seeds, schedule, iteration counts, BYOD switches and BYOD locations are form fields; outputs go to `outputs/raft_stereo/<run id>/outputs/` under the working directory.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
