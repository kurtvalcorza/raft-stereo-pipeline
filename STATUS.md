# Release status

Current status: **Candidate — initial development; checkpoint not yet pinned; no hosted execution evidence yet**.

What exists: the pipeline package (`src/raft_stereo_pipeline/`: pipeline, rendered samples, the carried upstream RAFT-Stereo `core/` at commit `6e93ed2169bd858dbb43033988563f3b0bb49506` verified by SHA-256), the offline test suite (the real upstream architecture with seeded random weights on small rendered pairs through estimation, fine-tuning, adapter export and reload; every tutorial stage in order for the sample and a BYOD folder; the pin tool on a fake archive), `MODEL_CARD.md` (Model Card Specification 1.2), and the standalone `E2E` / `GUIDED` tutorial `tutorials/raft_stereo_colab.ipynb` (generated by `tools/build_notebook.py` /3.1, DIMER Notebook Specification 2.2, isolated hash-locked uv environment, 38 cells).

What is not done:

1. **The checkpoint is not yet pinned.** `MODEL_REVISION` is `"unpinned"` and the manifest records no digest or size, because the archive host (Dropbox) was not reachable from the build environment. Until `python tools/pin_snapshot.py` is run where it is reachable (a Colab runtime works), the package refuses to load the checkpoint and the notebook stops at Section 3 with a message that says so.
2. **No hosted execution.** No Colab or Kaggle run of the notebook has been recorded, so no pretrained or adapted metric for this model exists in this repository. The tutorial's "Check your reasoning" notes therefore describe expected patterns, not recorded values.
3. **REL12 BYOD evidence** on a hosted runtime (one compatible folder, one incompatible `pairs.json`) is pending; the BYOD branches were exercised only locally with random weights.

Local evidence (2026-10-04, Linux CPU container, not hosted runtime evidence): the generated notebook ran top to bottom in a scratch copy of this repository in which a random-weight checkpoint of the real architecture had been pinned with `tools/pin_snapshot.py --archive` and pre-staged, with reduced fields (`N_PAIRS = 6`, `EPOCHS = 1`, `VALID_ITERS = 4`, `TRAIN_ITERS = 2`). Run A (both BYOD branches on, with a compatible 4-scene folder and one pair with ground truth) passed every cell in 347 s, including the real isolated install (uv 0.12.15 wheel verified, managed CPython 3.12.12, 35 hash-locked packages), every sample stage, the BYOD pair report, the BYOD dataset branch through `reload` and the fresh-process reload checks. Run B (the BYOD dataset branch pointed at a folder whose `pairs.json` names `../outside/im1.png`) completed the default path and then stopped, as intended, with `Stage 'prepare' failed (exit 2): ValueError: pairs.json entry 2: file '../outside/im1.png' must be relative to the dataset folder`. The metrics of these runs are meaningless (random weights) and are not reported. Details in `docs/release-verification.md`.
